**Status:** New — v0 source/spec/export-derived report  
**Slug:** `record-final-video` (absorbed; formerly the standalone `post-render-video-report` skill)  
**Draft location:** `docs/drafts/post-render-video-report.md`  
**Final location:** `apps/claude-remotion/.claude/skills/record-final-video/post-render-report.md`

---

## Purpose

After a Project Bright render/export, generate a structured report so that
downstream agents, the operator, and future pipeline steps can understand what
video was produced, what it contains, and what actions to take next.

The report is built from source artefacts — spec files, bridge project JSON,
production report, guided-job metadata, and generated component files — not
from watching the rendered MP4.

**Intended consumers:**

- Social post agents (caption and hashtag drafting)
- Publishing agents (scheduling, upload, metadata population)
- Archive and search agents (indexing, retrieval, versioning)
- Operator review before publishing (history, QA, sign-off)
- Future video agents that need to understand existing outputs without
  re-running the pipeline

**v0 honest scope:**  
This skill reads source, spec, and export artefacts only. It does not perform
visual analysis of the rendered video. Every v0 report must carry the source
honesty disclaimer described in § Critical Honesty Rule.

---

## When to Use

Use after any of these events:

- `export-susan-project.mjs` has run and `bridge_project.json` exists in the
  export directory
- `resume-guided-job.mjs` has completed Stage 2 and `production_report.json`
  is present in the job directory
- Video Bright has produced a preview render and a `video_url` is available in
  `guided-job.json`
- The operator wants an agent-readable summary before publishing to
  Bluesky, YouTube, or LinkedIn
- A downstream social post agent needs structured input about the video's
  content, text, brand, and CTA

---

## When Not to Use

Avoid when:

- The video must be **visually verified** before use. The source-derived report
  is not a visual QA gate. Use the still-preview gate or human review instead.
- The render failed, the MP4 is corrupt, or export files are absent or empty.
- No source/spec/export artefacts exist — there is nothing to read.
- Legal or compliance claims require direct human review of the video
  frame-by-frame. A source-derived report cannot satisfy those requirements.
- A publishing agent requires guaranteed visual accuracy — pair this report
  with a human sign-off step before automated publishing.

---

## Critical Honesty Rule

Every report generated by this skill in v0 **must** include this statement,
verbatim, in the report header:

> This report was generated from Project Bright source/spec/export artefacts,
> not by watching the rendered video.

Do not omit this line. Do not soften it or replace it with hedging phrases.

When actual frame or video analysis is added (a future enhancement), replace
the line with:

> This report includes frame-sampled visual analysis of the rendered video.

Until that capability is wired in, every v0 report is source-derived only and
must be labelled as such.

### Confidence levels

| Value | Criteria |
|-------|----------|
| `"high"` | `bridge_project.json` + `production_report.json` + Susan export JSON all present; `review_flags` is empty; `human_review_needed` is false |
| `"medium"` | `bridge_project.json` present; at least one other artefact present; 1–2 review flags or `human_review_needed` not set |
| `"low"` | Only `bridge_project.json` present; or `production_report.human_review_needed` is true; or only one artefact found |

## Markdown Report Format

The Markdown report must contain the following sections in order.

**Header block:**
```
# Video Report: <video title>

> Source honesty note: This report was generated from Project Bright
> source/spec/export artefacts, not by watching the rendered video.
> Confidence: <high | medium | low>
```

**Video Summary section** — include:  
- Title, brand name, platform (from Susan export `intended_platform` or scene-spec)  
- Format/dimensions if known, else omit  
- Duration in seconds (sum of `target_duration_seconds` from bridge slots)  
- Export directory (absolute path)  
- Video URL or "not yet published"  
- Job ID or "n/a"  
- Generated timestamp  
- 2–3 sentence summary of what the video does and who it is for

**Slot / Section Breakdown section** — a summary table followed by a detail block per slot:

Summary table columns: Slot | Type | Duration | Headline | Purpose

Per-slot detail block (one per slot in `bridge_project.json` order):  
- Slot ID and role_semantic as the heading  
- Duration, asset filename, headline (verbatim), description (verbatim)  
- Text on screen: list all viewer-facing text strings verbatim  
- Visual summary: from `description`, `notes`, and scene-spec `visual_treatment` if available  
- Review notes: any `review_flags` from `production_report.json` that reference this slot, or "None"

**CTA section:**  
CTA text (verbatim), URL if known, slot where it appears.

**Assets Used section** — table:  
Slot | File | MIME type | Size (bytes or "unknown")

**Brand / Style Notes section:**  
Brand name, handle, palette (primary/accent/background/text as hex), logo used (yes/no).

**Quality / Review Notes section:**  
List all `review_flags` from `production_report.json` verbatim.  
Include `plan_following_score_self_assessed` if present.  
Write "None" if `review_flags` is empty.

**Known Limitations section:**  
Always include: "This report was generated from source/spec/export artefacts — the rendered MP4 was not watched."  
Add any further limitations (missing artefact, inferred field, etc.).

**Downstream Agent Hints section:**  
- 2–3 suggested caption angles (tweet-length, derived from slot headlines + CTA)  
- 3–5 hashtags (relevant to brand and content, not generic)  
- Posting notes: any actionable flags (e.g. "review s6 before publishing — review_flag present")

**Source Artefacts section** — table:  
Artefact | Path | Status (Found / Not found)

## Workflow

Work through these steps in order. Log progress to stdout using the prefix
`[post-render-video-report]`. Do not fail silently — print a clear message
for each missing optional artefact and continue.

**Step 1 — Locate directory.**  
Determine the job directory or export directory. Print the path being used.

**Step 2 — Read `bridge_project.json`.**  
Required. Extract: `meta.title`, `slots[]` (all fields), `schema`, `version`.  
If not found and not found in `production_report.render_results.bridge_project_path`,
stop and report an error.

**Step 3 — Read `production_report.json`.**  
Optional. Extract: `overall.status`, `overall.plan_following_score_self_assessed`,
`review_flags[]`, `human_review_needed`, `render_results.slots_ok`,
`render_results.export_dir`, `render_results.bridge_project_path`.  
Log if not found.

**Step 4 — Read `guided-job.json`.**  
Optional. Extract: `job_id`, `brand_slug`, `plan_path`, `session_id`,
`artifact_id`, `vb_api_url`, `export_dir`, `video_url`, `completed_at`.  
Log if not found.

**Step 5 — Read scene-spec JSON.**  
Optional. Find via `guided-job.json → spec_path` or look for `scene-spec.json`
in the job directory. Extract per-slot `visual_treatment`, `colour_tone`,
`animation_direction`, `remotion_hint`, `timing_rhythm`.  
Log if not found.

**Step 6 — Read Susan export JSON.**  
Optional. Path from `guided-job.json → plan_path`. Extract:
`production_handoff`, `slot_story_map`, `cta`, `colour_palette`,
`brand.name`, `brand.handle`, `intended_platform`,
`project_context.website_url`, `project_context.cta_link`.  
Log if not found.

**Step 7 — Read generated component files (last resort).**  
Only read `generated/<brand_slug>/S*.tsx` and `V*.tsx` if text strings or
palette details are unavailable from the artefacts above. Do not read
component files as a first resort. Log which files were read if used.

**Step 8 — Build slot list.**  
For each entry in `bridge_project.json → slots[]`:
- Start with `slot_key`, `role_semantic`, `headline`, `description`, `notes`,
  `target_duration_seconds`, `asset.local_file`, `asset.mime_type`.
- Enrich with scene-spec `visual_treatment` and `animation_direction` if available.
- Add any `review_flags` entries that reference this slot ID.
- Collect all viewer-facing text into `text_on_screen` (verbatim, no paraphrasing).

**Step 9 — Extract CTA.**  
Check in this order until found:  
1. Susan export `cta` field  
2. `slot_story_map` entry for `s7`  
3. `bridge_project.json` slot `s7` headline/description/notes  
4. `bridge_project.json` slot `s8` headline/description/notes  
5. `project_context.cta_link` from Susan export  
If no CTA found, write `null` — do not invent one.

**Step 10 — Compute totals.**  
Duration = sum of `target_duration_seconds` from all bridge slots.  
Dimensions from scene-spec `platform` or `production_format` if present, else `null`.  
Aspect ratio inferred from dimensions or platform, else `null`.

**Step 11 — Determine confidence level.**  
Apply criteria from the confidence table above.

**Step 12 — Build downstream hints.**  
- 2–3 caption angles: short, tweet-length ideas grounded in slot headlines and CTA text.
  Do not invent claims not present in the source artefacts.
- 3–5 hashtags: directly relevant to brand name, product name, and slot content.
  Avoid generic hashtags like `#video` or `#socialmedia`.
- Posting notes: one bullet per actionable flag (review_flags, human_review_needed,
  missing artefacts that may affect accuracy).

**Step 13 — Write `video_report.json`.**  
Write to the job/export directory. Print the path.

**Step 14 — Write `video_report.md`.**  
Write to the job/export directory. If file exists, append timestamp suffix and warn.
Print the path.

## Rules

1. **Never claim to have watched the MP4** unless frame or video analysis was
   actually performed in this session. The source-honesty line is not optional.

2. **Quote viewer-facing text verbatim.** Do not paraphrase or rewrite slot
   headlines, CTA text, or description copy. If it appears in a source artefact,
   reproduce it exactly.

3. **Mark inferred fields clearly.** Append `(inferred)` to any field value that
   was derived rather than read directly from a source artefact.
   Example: `"audience": "developers building SaaS tools (inferred from Gate 1 summary)"`

4. **No secrets or credentials.** Do not include API keys, service tokens,
   session cookies, auth headers, or passwords in any report output. If a secret
   appears in a source artefact being read, skip that field entirely.

5. **Write `null` for missing fields, not a guess.** If a field is not present in
   any available artefact, write `null` in JSON and `"unknown"` in Markdown tables.
   Never fill in plausible-sounding values.

6. **Downstream hints must be grounded.** Caption angles and hashtags must derive
   from content actually present in the source artefacts. Do not invent marketing
   claims not supported by the slot text or production handoff.

7. **Do not fail on missing optional artefacts.** Log each missing artefact and
   continue. A partial report with clearly labelled gaps is more useful than a
   failed run.

8. **Do not silently overwrite existing reports.** If `video_report.md` already
   exists, print a warning and write to a timestamped filename instead.

9. **Keep downstream hints short and actionable.** Caption angles: tweet-length
   (≤280 chars). Hashtags: 3–5 specific tags. Posting notes: one clear action per
   bullet.

## Future Enhancements

The following are out of scope for v0 and noted here so the design does not
accidentally foreclose them.

| Enhancement | What it adds |
|-------------|-------------|
| **ffprobe metadata** | Real duration, codec, bitrate, pixel format, and exact dimensions read directly from the MP4 — no inference |
| **Sampled-frame extraction** | Pull 3–5 frames at 0 %, 25 %, 50 %, 75 %, 100 % of duration via `ffmpeg`; include as thumbnails in the report |
| **Visual frame analysis** | Pass sampled frames to a vision model to verify text on screen, brand colour, layout, and CTA placement; upgrade `confidence` to `"verified"` |
| **Transcript/caption extraction** | Extract embedded captions or audio transcript from the MP4 |
| **Automatic report hook** | Trigger `post-render-video-report` automatically at the end of Stage 2 in `resume-guided-job.mjs` |
| **Report versioning** | Add `report_id` and a sequential version number so multiple reports for the same job can coexist without overwriting |
| **Social caption generation** | Extend `downstream_hints.suggested_caption_angles` into fully drafted captions, ready for review and scheduling |
| **Step-sequence support** | Extend to read a `StepSequence` plan directly, so a step-by-step render is recorded from its `plan.ts` rather than from the composition |

**Automation priority note:**  
Do not wire the automatic report hook (`resume-guided-job.mjs` integration) until:

1. The generated-video-recipes experiment is stable and producing real outputs
2. Still-preview gate Slice 2 (`APPROVED` marker check in `resume-guided-job.mjs`) is
   implemented and validated on a real render
3. At least one full guided render has been reviewed end-to-end with this skill
   invoked manually, and the report has been confirmed accurate by the operator
